# 05. ブログ・SNS 連携／自動投稿の設計

> このドキュメントで決めること：**記事をどこに書き、どこへ自動で流し、どこは人が手でやるか。**

最終更新：2026-09-22

---

## 1. 結論（先に）

| やりたいこと | 自動化できるか | 手段 |
|---|---|---|
| ブログ記事を HP に反映 | **できる（自動）** | フィード取り込み＋定期ビルド。コスト0 |
| ブログ更新を X に投稿 | **できる（自動）** | X API v2。無料枠で足りる見込み |
| ブログ更新を Instagram に投稿 | できる（が**おすすめしない**） | Instagram Graph API。要画像・要審査・トークン更新の手間 |
| Instagram の予約投稿 | **できる（コード不要）** | Meta Business Suite の予約投稿。無料 |
| Google ビジネスプロフィールへの投稿 | 条件付き | API は利用申請が必要【要確認】 |

**一番効くのは「書く場所を1つに決めること」。** 自動投稿の仕組みより、こちらが先。
3箇所に別々に書いている限り、どこを自動化しても手間は3分の1にしかならない。

## 3. 推奨構成：HP を原本にする

```
               ┌──────────────┐
  記事を書く → │  HP（CMS）   │ ← ここ1箇所にだけ書く
               └──────┬───────┘
                      │ 公開ボタン
        ┌─────────────┼─────────────┬──────────────┐
        ▼             ▼             ▼              ▼
   HP に掲載      X に自動投稿   Instagram      Google
   （自動）        （自動）      （通知→人）   ビジネス
                                                （人 or API）
```

**なぜ HP を原本にするか**

1. 検索で拾われるのは自社ドメインであるべき。Blogger に本文があると、SEO の資産が Google 側に溜まる
2. 同じ本文が2箇所にあると、検索エンジンがどちらを本物か迷う（重複コンテンツ）
3. 04-tech-and-ops.md 4章で「161本を移行する」と既に決めている。ここと整合する

**判断：【要記入：HP を原本にする／ブログを原本にして HP に取り込む】**

## 4. パターン別の作り方

### 4-A. HP を原本にする場合（推奨）

| 工程 | 仕組み | 実装量 |
|---|---|---|
| 記事を書く | microCMS の管理画面（ブラウザ） | 0 |
| HP に反映 | microCMS の Webhook → Cloudflare Pages の Deploy Hook | **設定のみ・コード0** |
| X に投稿 | Webhook → Cloudflare Workers → X API | 小（50行程度） |
| Instagram | Webhook → 担当者に通知（メール/LINE）→ 人が写真を選んで投稿 | 小 |

公開ボタンを押すと数分で HP に載る。ここまでは**コードを1行も書かずに設定だけで実現できる**。

### 4-B. ブログ（Blogger）を原本にして HP に取り込む場合

| 工程 | 仕組み |
|---|---|
| 記事の取得 | `https://<ブログのURL>/feeds/posts/default?alt=rss`（RSS／Atom）をビルド時に取得 |
| HP に反映 | Astro が静的ページを生成（`/blog/[slug]`） |
| 再ビルドの合図 | **Blogger には Webhook がない** → GitHub Actions の定期実行（例：1日2回）で Deploy Hook を叩く |

注意点：

- 記事を書いてから HP に載るまで**最大で定期実行の間隔ぶん遅れる**（1日2回なら最大12時間）
- 本文が Blogger と HP の両方に出るため、重複コンテンツ対策が要る
  - 対応案1：HP は冒頭数行＋「続きを読む（Blogger へ）」にする（SEO 効果は弱い）
  - 対応案2：HP を原本に切り替える（＝ 4-A。推奨）
- ブラウザ側で RSS を読んで表示する方式は、検索エンジンに本文が載らない。一覧の飾り以上には使わない

## 5. 各サービスの技術的な条件

### 5-1. X（旧 Twitter）

| 項目 | 内容 |
|---|---|
| 方法 | X API v2 の投稿エンドポイント |
| 必要なもの | X 開発者アカウント、アプリ登録、APIキー |
| 無料枠 | 月あたりの投稿数に上限あり（数百件程度）【要確認：最新の枠を公式で確認】 |
| 月に数本のブログ告知 | 無料枠で十分に収まる |
| 向いている使い方 | 「タイトル＋URL＋ハッシュタグ」の告知 |

X はテキスト中心なので、ブログ告知の自動化と最も相性がいい。**ここから始めるのが現実的。**

### 5-2. Instagram

| 項目 | 内容 |
|---|---|
| 方法 | Instagram Graph API のコンテンツ公開機能 |
| 必須条件 | **プロアカウント**（ビジネス／クリエイター）であること |
| 必要なもの | Meta の開発者アプリ登録、アクセストークン、場合によりビジネス認証・アプリ審査 |
| 画像の渡し方 | ローカルファイルを直接アップロードできない。**公開URLに置いた画像**を指定する方式 |
| 投稿数の上限 | 24時間あたり25件程度【要確認】 |
| **運用上の最大の注意** | アクセストークンが**約60日で期限切れ**。自動更新を組まないと、ある日静かに投稿が止まる |

**おすすめしない理由**：Instagram は写真が主役のため、ブログ本文を機械的に流しても反応が取れない。
一方で審査・トークン管理という一番重い運用負荷を抱え込むことになる。割に合わない。

**代わりの案（無料・コード不要）**：Meta Business Suite の予約投稿。
週に1度まとめて写真を選び、7日分を予約しておく。実質的な手間はこれで十分減る。

### 5-3. Google ビジネスプロフィール

| 項目 | 内容 |
|---|---|
| 方法 | Business Profile API の投稿機能 |
| 条件 | API 利用には申請・審査が必要【要確認】 |
| 現実的な運用 | 当面は手動。ただし車の整備・販売業では**来店への影響が大きい**ので、更新自体は止めない |

### 5-4. Blogger（原本を HP に移した後）

Blogger を残す場合、API で「タイトル＋リンクだけの短い記事」を自動投稿して、本文は HP に誘導する形にできる。
ただし記事数が増えるほど管理対象が増えるため、**移行完了後は Blogger を閉じて 301 リダイレクトする**のが素直（→ 04-tech-and-ops.md 4-2）。

## 6. 費用

| 項目 | 費用 |
|---|---|
| ブログ → HP 反映 | 0円（Cloudflare Pages ＋ GitHub Actions の無料枠） |
| X 自動投稿 | 0円（無料枠内の場合）／超過時は有料プラン【要確認】 |
| Instagram 自動投稿 | API 利用自体は0円。かかるのは構築と保守の工数 |
| Instagram 予約投稿 | 0円（Meta Business Suite） |
| microCMS | 無料枠あり／有料は月数千円（→ 04-tech-and-ops.md 2-2） |

**現金の出費はほぼ発生しない。** かかるのは初期構築の工数と、トークン更新などの保守。

## 7. 進め方（段階を分ける）

| フェーズ | やること | 前提 | 効果 |
|---|---|---|---|
| 1 | Instagram・X の**予約投稿機能**を使い始める | 今すぐ可能。コード不要 | 投稿作業をまとめられる |
| 2 | ブログ記事を HP に反映（自動） | 新 HP の公開 | 記事が自社ドメインの資産になる |
| 3 | 公開したら X に自動投稿 | フェーズ2 | 告知を書く手間が消える |
| 4 | Instagram の自動投稿 | フェーズ3 ＋ 必要性の確認 | ※本当に必要かを見てから判断 |

**フェーズ4 は「やらない」という結論も十分あり得る。** 先にフェーズ1〜3で手応えを見る。

## 8. 自動化する前に決めておくこと

- [ ] 誤字のまま全SNSに出る事故を防ぐため、**公開前に人が確認する工程を1つ残す**
- [ ] 自動投稿が止まったことに気づける仕組み（失敗時に通知を飛ばす）
- [ ] APIキー・トークンは GitHub のコードに書かない（Actions の Secrets／Cloudflare の環境変数に置く）
- [ ] 各SNSアカウントの管理者が誰か。退職・引き継ぎで止まるのが一番多い失敗
- [ ] 自動投稿の文面テンプレート（タイトル／URL／ハッシュタグの形）

## 10. 見送り案

| 案 | 見送る理由 |
|---|---|
| 全SNSを完全自動化する | 1箇所の誤りが全チャネルに拡散する。確認工程を1つ残すほうが安全 |
| 有料の投稿代行ツール（Buffer 等）を入れる | 月額が継続的にかかる。まずは各SNS標準の予約投稿で足りるか見てから |
| ブラウザ側で RSS を読んで HP に表示する | 検索エンジンに本文が載らず、SEO の資産にならない |
